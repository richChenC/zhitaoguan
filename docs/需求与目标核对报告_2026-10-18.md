## 4. 已确认的问题

以下优先级用于安排修复：P1 为影响数据归属、统计、位置或恢复范围的问题；P2 为流程、追溯或交付缺口。不是工程安全等级。

### F01 / P1：RPT 机组号冲突未被拦截

- 位置：`src/backend/server.py:441`、`:875`。
- `parse_report` 使用 SUM 的机组上下文，未保留或核对 `ReportEntry.Id`；关联阶段只核对 Row/Column/Entry 等条件。
- 隔离复现：RPT Id=3，SUM Unit=2，仍接受 1 条记录，`reference_errors=[]`。
- 影响：冲突记录可能归属到 SUM 机组并套用其奇偶映射。
- 验收：机组冲突进入可追溯异常并隔离；报告与 SUM 原始值均保留。

### F02 / P1：同分析人员跨数据组相同缺陷未识别

- 位置：`src/backend/server.py:138`、`:450`、`:996`。
- 业务键及来源键包含 Calgroup 等采集身份，不能单独完成跨组相同缺陷识别。
- 隔离复现：同一大修、管子、分析人员及缺陷内容，分别置于两个 Calgroup，插入 2 条、跳过 0 条、重复审计 0 条、质量异常为空。
- 影响：统计重复计数，也可能把历史匹配变成多个候选。
- 验收：保留所有采集与报告证据，单独识别业务重复并明确统计选用规则；不能简单删除所有同管记录，一个管子可以有多个真实缺陷。

### F03 / P1：三维物理轴向定位尚未完成，旧缺陷已有代码更新

- 初次核对的 `app.js:360` 中，旧 `defectY` 将未知位置默认 P3，负偏移丢失，并使用任意 400 mm 比例；这是初次检查发现，不再作为后续复核时的现存代码描述。
- 补查聊天/记忆时发现当前文件已有其他修改：`src/desktop-ui/visualizations/thimble/defect-location.js:2` 返回有效 P 位与有符号偏移，未知位置返回 null；`app.js` 已按新函数生成点，并说明“P 位示意；轴向偏移未标定”。
- 当前限制：`y` 仍为对应 P 平面值，尚未使用确认的物理距离把偏移换算到真实轴向坐标；这属于已说明的示意限制，不能再描述为未知位置默认 P3。
- 本次只更新核对文档，未修改该业务代码；尚未针对新实现完成整套三维渲染验收。
- 验收：负偏移、单位、基准点和物理距离可追溯；未知位置明确待确认；真实偏移完成标定；完成奇偶映射及二维/三维一致性验证。

### F04 / P1：自动最新报告策略绕过人工选择

- 位置：`src/desktop-ui/software-settings.js:11`、`:78`、`:136`。
- 前端允许“自动选择最新 Report”，自动标记各组已确认并提交报告列表。
- 后端在没有明确选择列表时的多版本拦截，不能证明这些前端提交已经过人工确认。
- 验收：候选建议与最终确认分开，最终采用版本由操作人员明确确认，保存确认人、时间及候选证据。

### F05 / P1：恢复一个删除批次会恢复无关导入批次标记

- 位置：`src/backend/server.py:2483`。
- `UPDATE import_batches ... WHERE is_deleted=1` 没有限制目标删除批次。
- 隔离复现：恢复 A 后，A 与无关 B 的 `is_deleted` 均变成 0。
- 影响：导入批次元数据恢复范围超出用户选择，与记录恢复范围不一致。
- 这是回收站恢复问题；新导入审计的 `change_batch` 批次回滚/恢复测试通过，不能用后者替代前者验收。
- 验收：只恢复目标批次关联内容，其他批次不变化；元数据与业务数据一致。

### F06 / P2：管状态与报告导出审计不完整

- 验收：状态新增、修改、撤销和报告导出均可追溯，保留对应快照、规则版本及来源。

### F07 / P2：报告格式之间的追溯信息不一致
