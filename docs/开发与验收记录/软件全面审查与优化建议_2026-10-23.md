# 软件全面审查与优化建议

审查日期：2026-10-23  
审查对象：`01_当前软件/软件正式版_20261021`（Electron 壳 + Python 后端 + 原生 JS 前端）  
审查方式：实际启动后端（`THIMBLE_PORT=18767 python src/backend/server.py`），用 Playwright 逐屏巡检 6 个导航视图、
1366×768 / 1440×860 / 1600×950 / 1920×1080 四档分辨率、抓取全部 console 报错与网络资源，
并对 17 个 CSS 的设计令牌做静态比对。**所有结论都有实测数据，不靠观感。**

---

## 〇、先说结论

软件的整体完成度很高：六个导航齐备、数据真的来自本地 SQLite（首屏 16 个接口、2.66 MB 数据）、
管板图与三维模型都在跑、首屏可交互约 360 ms。

但**视觉一致性有一处硬伤**：主色被三处 CSS 互相覆盖，同一个 `.primary` 按钮在不同视图是**两种颜色**
（报告中心"导出报告单"是蓝 `rgb(23,105,168)`，其余视图是青绿 `rgb(8,125,121)`）。
另有 52 条 SVG 渲染报错、约 700 KB 的 three.js 被加载了两份、三维视图键盘不可达。

下面按"设计 / UI / 排版 / 布局 / 功能 / 优化 / 未来调整"七部分给建议，每条都标了**证据**和**工作量**。

---

## 一、UI 设计

### 1.1 主色有三套在互相覆盖（必修）

`--primary` 在 5 个文件里有 3 种值，最终渲染值由 CSS 加载顺序决定：

| 文件 | `--primary` |
|---|---|
| `app.css`、`polish.css` | `#0055a4`（CGN 蓝） |
| `desktop-theme.css`、`interface-polish.css`、`workbench.css` | `#087e80` / `#087d79`（青绿） |

实测 `getComputedStyle(documentElement).getPropertyValue('--primary')` = `#087d79`（青绿赢）。
但 `reports` 视图的"导出报告单"按钮背景仍是 `rgb(23,105,168)`（蓝）——**同一个类，两个颜色，用户看得见**。

同类冲突共 **13 个令牌**：`--bg`（6 种值）、`--ink`（6 种）、`--line`（6 种）、`--muted`（6 种）、
`--primary`、`--primary-dark`、`--focus`（4 种：金/青/青/青）、`--danger`、`--red`、`--red-dark`、`--green`、`--blue`、`--paper`。
7 个 CSS 各自写了一份 `:root`，**没有单一事实源**。

> **建议**：新建 `tokens.css` 作为唯一定义处，其余 7 个文件的 `:root` 全部删除、只做引用。
> 主色二选一后全局替换——建议保留青绿 `#087d79`（已被绝大多数视图使用，改动面最小），
> 把 `#0055a4` 那一支统一过来。改完主按钮底色集合应当只剩 1 种。

### 1.2 三维视图是另一套视觉体系

三维视图由 iframe（`visualizations/reference-thimble/index.html`）承载，实测：

- iframe 内 `--primary` = **空串**（没定义主色令牌）
- iframe body 底色 `rgb(238,242,247)` vs 主界面 `rgb(242,245,247)` —— **切换视图时底色会变**
- 字体栈一致（Microsoft YaHei UI），这点是好的

> **建议**：iframe 的 HTML 也 `<link>` 同一份 `tokens.css`，至少把底色、主色、focus 色对齐；
> 中长期按 5.1 并入主文档。

### 1.3 没有深色模式

全库无 `prefers-color-scheme` / `data-theme`。核电值班室、夜间巡检场景下长时间看浅蓝白底容易疲劳。

> **建议**：令牌集中后，加一份 `tokens.dark.css` + 设置里一个"主题"下拉即可支持，成本很低。

### 1.4 语义标签使用失当

实测页面有 **201 个 `<header>` 元素**（`.panel-title` 一类都用了 header）。
`<header hidden></header>` 是一个空元素，从未使用。

> **建议**：`.panel-title` 改用 `<div class="panel-title">` + `aria-label`，或统一成 `<h2><span>` 结构；
> 删掉空 header。

## 二、排版

### 2.1 数据可视化页信息密度失衡（最影响体感）

该页实测 15 个 panel、9 个 SVG、3 张表，但第一屏只有「KPI 总览 + 各机组检测覆盖面」两块，
**三张核心图（图3.1 群厂磨损增量、图3.2 P1-P5 趋势、图3.4 管板更换分布）全在折叠线以下**。
用户进页面第一眼看不到最重要的东西。

> **建议**：把页面切成"实时分析区 / 核心三图区 / 参考数据区"三段，
> 核心三图用 tab 或固定吸顶分组；参考性质的内容（F2 专题、宁德 C1–C8、关键发现）收进"参考资料"折叠区并明确标注"参考资料，非本机实时"。

### 2.2 报告中心空态占满整屏

未选择基地/机组/大修时，右侧预览区是完全空白，只有一行小字。第一屏信息量很低。

> **建议**：空态改为"引导卡片 + 最近一次报告缩略 + 操作步骤 1/2/3"，
> 让用户知道选完会出现什么；顺带把"表头与设置信息"折叠起来（现在是展开占 1/3 屏）。

### 2.3 字号与行高的可读性

- 说明性文字多处 9.5 px（`.plan-note`、`.chart-legend-note`），1440 以下偏小
- 表格行高偏挤，NDD 行用 `/` 占位，视觉噪声多

> **建议**：正文不低于 12 px，说明文字 10.5–11 px；表格给 NDD 行统一显示"—"并降透明度，比 `/` 更安静。

## 三、布局

### 3.1 1366 下报告中心横向溢出 5 px

实测 `DIV.report-center.rc-workspace 1316 > 1311`、`DIV.rc-topbar 1316 > 1311`、
`BUTTON.rc-icon-button 36 > 30`。1366×768 是笔记本常见分辨率，会出现横向滚动条。

> **建议**：给 `.rc-workspace` 加 `min-width:0` 并让 `.rc-topbar` 允许 `flex-wrap`；
> 全站做一遍"最小支持宽度 1280"的溢出扫描（已有 `_audit_ui.mjs` 可直接复用）。

### 3.2 管板图容器潜在溢出

实测 `DIV.reference-grid 490 > 426`、`DIV.flow-mark.corner 75 > 54`（`overflow-x: visible`）。
当前分辨率下视觉没破，但窗口再窄就会撑破容器。

> **建议**：`.core-map` 外层加 `overflow:hidden` 或让 reference-grid 用 `width:100%;height:auto` 的 SVG 方案。

### 3.3 状态页 232 行全量渲染，无分页

实测已维护记录 232 行**全部在 DOM 里**，整页 19759 个节点。记录上千后会明显卡顿。

> **建议**：与工作台一致加分页（每页 50），或做虚拟滚动；表格上方筛选已有，加个"每页条数"即可。

### 3.4 响应式策略缺失

四个分辨率下导航始终是 6 个按钮横排。1280 以下文字会被挤压，但没有断点处理。

> **建议**：≤1280 时导航收成图标 + tooltip，或允许换行；至少保证不溢出。

## 四、功能

### 4.1 三维视图的 iframe 方案带来一串连带问题

| 问题 | 实测 |
|---|---|
| three.js 加载两份 | `vendor/three.module.min.js`（主壳）+ `reference-thimble/vendor/three.core.min.js`(372 KB) + `three.module.js`(331 KB) = **约 700 KB 冗余** |
| 应用代码两份 | 主 `app.js`(93 KB) + iframe `app.js`(135 KB) |
| 键盘不可达 | 焦点进入 iframe 后 Tab 12 次 + Shift+Tab **全部停在 iframe 本身**，键盘用户进去出不来 |
| 52 条 SVG 报错 | `<line>/<circle>/<text>` 的 x1/cx/x 为 `NaN`，来自 iframe 内图元（最终 DOM 已被修正，但控制台一片红） |
| 主题不共享 | 见 1.2 |

> **建议**：短期给 iframe 补 `title`/`tabindex`/`Esc 退出`，并定位 NaN；
> 中长期按 5.1 合并。

### 4.2 index.html 里有死代码

`#importDialog`（"处理检测文件夹"旧版对话框）写在 index.html 里，但实际对话框被 JS 换成了
"文件夹解析与 Excel 导入"两步流程。旧 dialog 的按钮 id（`selectFolderBtn`/`runImport` 等）已无人绑定。

页面同时存在 5 个 dialog：`iqConfirm`（回滚确认）、`importDialog`、`reportPreviewDialog`、
`reportChoiceDialog`（Report 选择）、`restoreDialog`（恢复数据库）。

> **建议**：删掉旧 `#importDialog` 静态节点；把 5 个 dialog 的打开/关闭/焦点圈禁收敛到一个 `dialog.js`
> （统一 Esc 关闭、打开时焦点入圈、关闭后焦点归还），顺带解决 4.1 的键盘问题。

### 4.3 资源版本号管理混乱

CSS/JS 的 `?v=` 参数有 10 种写法（`20260831b`、`20261020-original-forms`、`20261023-plate-grid`…），
同一文件的版本号在不同提交里风格不一，容易漏改导致用户拿到旧缓存。

> **建议**：改成统一 `?v=<SERVICE_VERSION>`，由 `server.py` 的 `SERVICE_VERSION` 一处注入
>（后端已在返回 HTML 时可做），前端不再手写。

### 4.4 首屏拉 2.66 MB 接口数据

16 个 XHR/fetch、2.66 MB。台账索引、明细、图表数据全部在进页面时请求。

> **建议**：按视图懒加载——切到"数据可视化"再拉 analytics 数据，切到"报告中心"再拉报告数据；
> 首屏只保留工作台必需的记录列表与字典。

## 六、未来调整（结构性，建议排期）

### 6.1 三维模型并入主壳，去掉 iframe
这是**收益最大的一项**。合并后：主题/字体/焦点统一，键盘可达，省 700 KB，
状态（当前选中的管位）可以和左栏表格、管板图真正联动，而不是靠 postMessage 桥接。
合并时直接沿用 `指套管模型工程/04_三维查看器/app.js`（那套已做过双相机、正交俯视、细管吸附、自适应手风琴），
比把 iframe 里的旧版往前搬更省事。

### 6.2 建一套组件规范
现在按钮有 3 种底色、5 种高度；表格、筛选条、空态、toast、dialog 各自为政。
建议沉淀出 `.btn/.btn-primary/.btn-ghost`、`.field`、`.table`、`.empty`、`.toast`、`.dialog` 一套基础类，
新功能只组合不再造。这也是 1.1 不再复发的根本解。

### 6.3 数据可视化页支持"大屏/投屏模式"
该页本来就是给会议室大屏设计的（图表多、KPI 大）。加一个 F11 全屏布局（隐藏导航、放大 KPI、
图表两列变三列），汇报时直接可用。

### 6.4 键盘与无障碍补齐
- 11 个 input 无 `label`（只有 placeholder）
- 实测 focusable 元素 1881 个，但没有统一的 `:focus-visible` 样式
- 建议：导航支持 `1–6` 数字键切换视图、`Ctrl+F` 聚焦筛选、`Esc` 关闭 dialog / 退出三维
- focus 环统一用 `--focus`（当前这个令牌本身就有 4 种值，先按 6.2 治理）

### 6.5 深色模式
见 1.3。令牌集中后成本很低，适合值班场景。

### 6.6 视图状态记忆
用户切走再回来，筛选条件、滚动位置、选中的管位都应恢复（三维查看器已用 localStorage 做过
`viewer.grpCollapsed.v2`，可推广到主壳）。

### 6.7 审计与日志可视化
后端已有 `import_audit.py` / `operation-log-viewer.js`，但只在设置里能看到。
建议在工作台加一个"导入批次与操作审计"侧栏，异常记录可一键定位到原文件/行号
（方案里要求的"异常中心"落地形态）。

### 6.8 安装包与自动更新
`electron-builder` 已配好 NSIS/便携版。建议加 `electron-updater` + 本地更新源（保持离线可用），
并把 `SERVICE_VERSION` 一并用于更新校验。

## 七、本次审查未覆盖的部分

- `src/backend/server.py`（约 220 KB）未逐行走查；该文件按项目约定**冻结禁改**，仅确认了启动参数
  （端口 `THIMBLE_PORT` 默认 18767、静态根 `src/desktop-ui`、无 Bearer 鉴权）与服务可用。
- 导入解析的**正确性**（ECT/RPT/SUM 解析、管号校验、R/NI 判定、移位 42 mm 换算）未做数据级回归，
  只验证了界面链路可走通。建议另立一轮"用大亚湾/宁德/红沿河/防城港/阳江样本集跑业务断言"。
- 报告导出的 Word/Excel 内容未逐字段核对。
