# 可视化需求反馈实施记录

日期：2026-11-01

## 本次落实

- 软件设置新增全局“图表数值标注”开关，趋势图、P 位趋势和单次检查通道图可统一显示/隐藏数值。
- 图表悬浮提示改为简洁优先，保留范围、机组、通道/位置、深度、轮次和状态等关键字段；减少重复统计说明。
- 单管纵向磨损对比增加“显示全部 50 根”切换；全部显示时降低线条权重，并保留通道号、堆芯位置和状态符号，避免只依赖颜色识别。
- 纵向对比继续使用状态联动：换管不计算跨管深度差，移位不作为深度增长，堵管保留事件标记。
- 单管纵向变化明细改为可折叠，默认先展示曲线和关键摘要。
- 单次检查深度分布的两个图表标题增加直接解释：直方图是深度区间与管数，通道图是通道号与最大报告深度。
- 奇数/偶数机组仍使用各自正式管号到堆芯位置的映射；本轮没有把编号或坐标混合。

## 校验

- `npm run check`：通过，81 个 ESM 文件检查通过。
- `git diff --check`：通过。
- `node tests/visualization_model_verify.mjs`：未通过一项既有阈值期望；该测试仍期待旧的 20/40 分级，而当前软件默认采用可配置的 30/50 分级。未将该旧期望伪报为本次功能通过。

## 边界

- “全部 50 根”曲线的颜色仅作辅助，精确区分以通道号、堆芯位置和悬浮信息为准。
- 数值标注打开后，通道密集图可能产生重叠；默认关闭，建议在少量机组/少量曲线时开启。
- 极限与关注阈值仍是可视化分级，不是维修或验收判据。

## 空白换管管板调整

- 按最新反馈，没有明确换管事件时仍保留管板网格、轮廓和坐标，不显示管号、状态色块、次数及数量图例。
- 右侧分别提示维护资料完整但未记录换管、维护资料缺失、未选择大修；不把资料缺失推断成零次换管。
- 切换到空白范围时清除已选管号和旧详情，切回有记录范围时恢复真实分布。
- 空白管板支持导出 PNG，附带对应的资料说明；文件名标明机组、所选大修、暂无明确换管记录及资料不全情况。
- 本轮复核：`npm run check`、可视化模型测试、状态变化模型测试、20 项后端可视化测试、完整可视化桌面回归均通过。此前记录的模型阈值期望问题在本轮测试中未再出现。
- 管板专项桌面测试通过 11 个场景，覆盖空白与有数据切换、浅色/深色主题、窄窗口、5 种 PNG 导出及加载失败重试；测试使用隔离数据库，真实数据库哈希保持一致。

## 换管统计口径核对

- “全库历史累计”来自可视化后端的 `lifetime_replacements`，按单根管发生过换管的大修去重后求和，选择单次大修筛选不会改变此总量。
- “所选大修明细”来自 `unit.history[].replacement_records`，逐条统计用户在大修选择器中勾选范围内的明确换管记录；维护记录不全时只作为已记录次数，不推断为完整总数。
- 后端增加每根管的 `lifetime_replacement_outages` 来源编号，用于将累计总账与可选择的大修明细进行对账；未匹配的事件显示次数和大修编号。
- 管板概览、单管详情、核查条均分开显示全库累计、所选明细及其他已选范围外的明细；全库没有明确事件时显示“暂无明确记录”，不显示无信息的零次数字。
- 换管视图标题及切换项改为“换管记录”，避免将可筛选的大修明细误称为固定累计值。
- 新增模型断言：全库累计与全部大修明细一致、缩小大修范围后其余事件单列、以及累计存在但大修明细无法匹配时列出未匹配编号。
- 本轮最终回归：管板专项 12 个场景、可视化分析桌面回归、完整可视化桌面回归均通过；后端 20 项测试、可视化模型测试及状态变化模型测试均通过。截图与导出验证使用隔离数据库。
- 之前记录的阈值断言旧口径和空白换管 UI 已按当前 30%/50% 设置、空白管板行为修订；本轮复跑 `npm run check` 时检查了 86 个 ESM 文件，全部通过。之前的 81 文件旧校验条目仅保留为当时记录，以本条复核结果为准。
