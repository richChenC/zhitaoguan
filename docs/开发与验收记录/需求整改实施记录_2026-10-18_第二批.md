# 需求整改实施记录（第二批）

本轮依据用户指定的主核对报告、聊天与记忆补充核对、原文汇编、来源清单和用户发言索引继续修改本地 Windows 工程。历史资料中的操作命令不作为本轮授权执行。原核对报告保留，以下记录实施后的增量状态。

## 本轮实现

| 核对项 | 修改与证据 | 当前边界 |
|---|---|---|
| F01 / M22 | 保留 `ReportEntry.Id` 原文；与 SUM Unit 冲突或无效时隔离，质量清单显示“RPT 与 SUM 机组冲突”；检查表附双方机组号和原始记录 | 缺少 Id 的历史文件仍按 SUM 上下文处理，不伪造原值 |
| F04 / M13—M15 | “最新 Report”改为建议；每组仍需人工确认。更改已确认版本后立即失效；后端检查全部有效候选、RPT/SUM 哈希、选组完整性。导入批次保存确认时间、操作人员及候选快照 | 直接调用 Python 内部解析函数仍保留既有测试/维护入口；软件 HTTP 导入和文件夹导出接口强制校验确认信息 |
| M07 / F04 | 修复软件导出列“三字符”无法被导入识别的问题；标准 Excel 携带“报告版本确认”表，后续入库保留其确认来源与哈希 | 从 Excel 带入的确认表标为 `imported_workbook`，不冒充导入时重新人工确认；Excel 文件本身另有哈希审计 |
| F02 / M19 | 按同大修、同机组、同管、同分析人员、跨数据组，以及位置/通道/幅值/相位/百分比/三字符/测量类型全相同识别；质量清单、文件夹检查表、报告预览列出待复核提示，保留全部来源 | **尚未完成统计代表记录的人工选择与全模块统一排重**。当前报告明确提示仍包含这些记录，不静默删除不同来源 |
| F06（状态） | 状态录入、修改、撤销事务内记录前后值、操作人员、时间和“该次检查后生效”；撤销采用软删除；维护界面新增可折叠修改记录；更新时间使用真实维护时间；维护操作通知工作台、报告预览和基地统计刷新，修复旧多大修对比仍引用已撤销备注的问题 | 沿用核对报告已公开的检查后生效约定，未新增未经确认的业务时点；历史操作不追补虚构人员和时间 |
| F06（导出） | 新报告中心成功导出 Word、Excel、CSV 后记录快照、范围、规则、来源、核查提醒、操作人员、服务版本、输出路径与 SHA-256 | 遗留独立导出入口、质量清单导出等尚未全部接入同一审计；F07 的各格式内附来源版式仍待统一 |
| F08（SET） | SET 文件仍保留哈希，但状态改为 `archived_unparsed`，不再声称已解析 | 尚未实现 SET 参数解析 |

软件与本地服务版本同步为 `2026.10.18.2`，用于识别需要匹配的本机服务。未新增独立网页产品，未重建安装包。

## 验证

- Python 回归通过：69 项，本轮新增机组冲突隔离、确认候选变化、SUM 变化、漏选、标准 Excel 往返、跨组重复边界、状态撤销与重录、撤销后多大修对比、快照失效和导出哈希审计测试。
- JS 检查通过：`npm run check`，覆盖现有脚本及 38 个 ESM 文件；另对 `software-settings.js` 执行语法检查。
- Electron 桌面验证通过：扩展 `tests/desktop_verify.mjs`，验证最新建议仍需确认、更改选择后失效、缺少确认的请求被拦截、生成检查表、状态修改记录；同时保留既有地图、报告、回滚恢复和三维像素检查。三维采样检出 728 种颜色；地图 10 个标记、大亚湾与岭澳共用坐标、无过大南海插图。
- 真实数据库只读复制后迁移：连续初始化两次，记录数 `5532 → 5532`，`PRAGMA integrity_check` 为 `ok`，新增状态历史为 0，未虚构旧操作记录。原业务数据库未被迁移或写入测试数据。
