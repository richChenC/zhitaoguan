# 导入故障修复与通知验证

验证日期：2026-11-03。修改范围为当前正式版源码；验证数据库和截图放在项目的 `05_测试与验证/`，未向日常使用的业务数据库导入测试记录。

## 已确认原因

日常使用数据库的失败批次 #1 记录为 `database or disk is full`。处理开始时 D 盘可用空间为 0；业务数据库只读 `PRAGMA quick_check` 返回 `ok`。

对 `05_测试与验证/03_自动化临时产物/软件正式版_tmp/` 中 675 个生成的测试数据库执行 Windows LZX 文件压缩后，可用空间恢复到约 42 GB。压缩可逆，未删除业务数据库、原始检测资料或历史版本。

另外，界面回归发现本地 HTTP 服务默认仅容纳 5 个等待连接，启动时部分脚本、样式请求出现 `ERR_CONNECTION_REFUSED`。当前服务等待队列扩大到 128；验证了尚未接收请求时的 24 个突发连接，以及真实桌面启动、登录和导入。

## 修复后的行为

- 导入前检查数据库卷及 RPT 转换输出卷的可用空间。空间不足时明确显示位置、剩余空间、所需空间和重试建议。
- 导入事务失败后回滚检测记录；能够写入审计时保留失败批次和原因，并关联准确批次。预检查失败不再尝试绕过检查直接写入。
- 失败结果直接显示具体原因，提供“查看批次详情”和“查看服务日志”。设置的“备份与维护”也有固定日志入口。
- 日志保留异常堆栈。查看接口只读取最多 128 KB 的日志尾部，并沿用审计查看权限。即使失败响应的审计写入也遇到磁盘写满，仍保留原始错误响应；成功响应仍要求审计正常。
- 默认通知显示 3 秒；悬停、聚焦时暂停隐藏。自动隐藏后仍可查看通知历史。撤销删除提示也采用同一时长设置。
- 设置的“界面与工作流”支持 3 秒、5 秒、不自动隐藏及提示音开关。默认 3 秒、提示音开启，保存后同步到主窗口。设置仍位于主窗口右上角，并使用独立窗口。
