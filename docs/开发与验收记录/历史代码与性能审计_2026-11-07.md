# Qt 历史代码与性能审计

日期：2026-11-07。范围：Qt 主版本的运行入口、源码盘点、静态资源引用和隔离 Qt 窗口测试。旧 Electron 与历史备份作为参照保留，未修改。

## 结论

确有历史残留，包括隐藏的旧分析面板、未接入当前页面的分析模块、Electron 兼容代码和重复 Three.js 文件。但是，磁盘上存在的旧文件不等于启动时加载；本轮没有同条件旧版本性能基线，不能据此断言某批遗留代码造成了全部性能退化。

当前工作台仍加载 23 个脚本（约 448 KiB）、26 个链接样式表（约 517 KiB），包含 4783 个 DOM 节点。启动期间记录到最长约 262 ms 的主线程长任务。切页事件处理通常很短，但后续绘制等待和首次模块加载仍明显，值得继续优化。

## 本轮修改

- 删除 `src/desktop-ui/index.html` 中仅靠样式隐藏的 7 个旧外层区块、9 个旧分析面板，HTML 从 37680 字节减至 29914 字节。保留当前分析图、导入对话框和设置。
- 修复 `lazy-modules.js` 的样式依赖：分析页也显式加载 `analysis-center.css`，避免布局取决于是否先进入报告中心；使用现有样式缓存防止重复加载。
- `scripts/source-audit.mjs` 将 `qt_shell/` 纳入盘点和 Python AST 检查，原工具遗漏了桌面壳。
- 重写 `tests/qt/perf_probe.py`，使用正式库的只读快照生成隔离副本，显式验证登录和业务页面就绪，在页面内测量导航，并按测试进程子树统计内存。
- 更新架构说明，使 Qt 启动链、用户数据路径与实际运行一致。

## 旧性能结论纠正

旧性能脚本未显式启用 Qt 测试数据根，登录失败后仍继续测量，导航轮询超时和整机进程差集污染了统计。旧报告中的每页约 6.7 秒、工作台启动时间及 181.8 MB 内存不能继续作为性能结论。本轮保留旧文件用于追溯，使用隔离报告作为新基线。

## 后续优化顺序

1. 根据主线程记录，减少工作台首屏样式、DOM 和切页后的重复布局、绘制；先建立同条件对照，再验证优化收益。
2. 拆清分析与报告共用样式职责，继续验证首次进入、反复切换和独立窗口。
3. 优化首次分析请求与三维初始化，保持非三维启动不加载模型。
4. 独立整理 Electron 兼容工具链、未接入模块与三方副本，同步处理测试和来源清单后再删除。

清理范围拟限定为本轮三个 `qt-perf-20261107-*` 精确沙盒中的数据库副本、缓存、截图和可重建输出，保留 `performance.json` 与日志。自动执行审批拒绝了该删除命令，未执行清理；这些临时文件仍保留在统一测试目录中。正式业务库和其他任务的测试目录未受影响。
