# RPT 文件夹导入优化与验证

日期：2026-11-02

## 导入流程

- 导入窗口分为“已有标准 Excel”和“原始 RPT 文件夹”两条路线，共用队列、进度和结果摘要。
- 扫描后逐组人工选择唯一 Report；候选项将分析人员缩写置于文件名之前，并用稳定的不同色标区分。选择可返回修改，未确认组会被定位。
- 一次点击自动生成并保存标准 Excel，随后检查字段并导入数据库。已保存文件可下载；取消三字符处理后重试会复用该文件。
- 缺失三字符时暂停写入，操作员可取消、保留空值供复核，或明确确认批量填入 WAR。
- 转换保留原始 RPT 备注、报告/数据来源及版本确认记录；由于原始 RPT 不含管状态，状态栏留空，备注不触发状态识别，也不覆盖现有管状态。普通 Excel 的原状态识别流程保持不变。
- 完成摘要区分新增、重复、无效、待核对、解析异常及三字符缺失；报告转换信息分别列出已确认 Report 数与扫描到的目录组数。
- 导入窗口采用紧凑来源切换、统一滚动工作区和固定底部操作；RPT 页面按“选目录 → 选择策略 → 确认报告 → 查看 Excel/结果”排列，桌面、390px 窄屏和深色模式均检查。
- 分析人员名在 Report 选择向导中优先呈现；完成结果提供新增、更新、重复和待核对数字摘要。

## 验证

- Playwright RPT 端到端：用项目 H209 原始数据，隔离数据库中新增 123 条；验证单击请求顺序为转换、字段检查、Excel 入库。
- RPT 边界：缺少 RPT、损坏 RPT、分析人员颜色、报告确认/取消与重试、缺失三字符的取消/空值/WAR、重复导入、无推断管状态、策略变更失效处理；桌面/窄窗口及深色模式布局通过。
- 其他桌面导入验证：导入向导、报告选择向导、部分成功/失败/重试、进度与 ETA 均通过；浏览器未发现脚本异常。
- 界面回归：Excel 初始窗口保持紧凑；RPT 桌面/窄屏底部操作可见；唯一的 390px 空态高度回归已修正。
- Python：`test_server.py` 44 项、`test_import_excel_xls.py` 9 项、`test_inspection_states.py` 16 项通过。涵盖原始备注保留、RPT 转换标记、旧 `.xls` 读取，以及普通 Excel 状态识别。
- `node --check`（相关前后端测试脚本）、`py_compile` 和本次涉及文件的 `git diff --check` 通过。

## 范围说明

上述验证针对 RPT/Excel 导入与相关状态保护路径，使用临时数据目录和测试数据库，不修改用户数据库。本记录不代表整个桌面软件所有功能均完成全量测试，也不代表 Windows 安装版/便携版已重新构建。
