# 工作台备注转管状态识别

## 处理规则

- 工作台导入 Excel 检测数据时，从原始 `备注` 与 `堵管移位信息`（含 `割管移位信息`、`维护状态`、`处理状态`、`管状态` 别名）字段识别堵管、换管、移位和明确的正常状态。来源保留实际原表列名。
- 本地 RPT 目录导入时，从原始 `Analysis` 与 `Comment` 字段识别相同的维护状态。
- 识别只读取规范化副本。规范化文本用于判断状态、管号、大修及位移，不写回备注。
- 明确且范围无冲突的记录随检测导入事务一并自动写入管状态。
- `割管移位`、`切管移位`、`移位`、`位移`归为移位；有明确状态即可导入，距离允许空白。`封堵`、`封管`、安装堵头归为堵管；`更换`、`替换`归为换管。
- 有距离但没有方向的移位记录可直接导入，原数值单独保存在“未确认方向的距离(mm)”中；有符号位移仍为空，不填零、不猜正负。百分比不是毫米距离。
- 计划、否定、解除封堵、历史处理、其他大修/管号、同管多种不同原文、同时记载多种状态，以及已存在或已撤销的维护记录，进入“核对识别结果”；不推断正常、不覆盖现有记录。
- 核对时原备注仍是原始文本。用户确认后才写维护记录；忽略只关闭待核对项，不删除检测记录或原备注。
- 导入来源单独保存在“来源”列。重复来源可合并在来源字段中，不附加到备注。
- Excel 与 Word 维护表均提供独立“备注”和“来源”字段。Excel 保留历次维护汇总；Word 的维护明细用于再次导入，避免汇总和明细重复识别。
- 撤销/恢复原始导入批次时，一并处理该批次自动识别及人工确认的维护状态；若维护状态后来被编辑，拒绝静默覆盖。
- 移位距离或方向未明确时，历次对比显示待确认，不自动换算缺陷位置；明确填写的零位移与未知距离分开处理。旧版已有的有符号位移及批次撤销/恢复保持兼容。

## 原文保留

导入与导出保留备注字符串中的首尾空格、全角字符、制表符、换行、回车换行以及看似来源标记但实际属于原文的文本。HTML 文本框显示 CRLF 时会规范呈现为换行；未编辑保存时，客户端使用原始值恢复原有 CRLF。状态解析产生的清洗文本只用于识别，不用于替换备注。

## 边界

自然语言无法无歧义判断的备注不会自动写入维护状态，会显示在待核对列表；检测备注及其来源保持原样。旧版本曾把来源文字附加进备注的记录无法安全地批量反拆，因为同样文字可能本来就是用户备注的一部分。
