## 1. 证据分级

| 等级 | 含义 | 采用方式 |
|---|---|---|
| A | 用户直接输入或最新明确说明 | 作为产品硬要求 |
| B | 业务人员/资料中明确提出的业务要求 | 作为业务要求，必要时由用户签字确认 |
| C | 从 ECT/RPT/SET/SUM 等文件结构验证出的事实 | 作为解析和数据治理规则 |
| D | AI 方案、历史实现、旧记忆或推断 | 只能作参考，不能覆盖 A/B/C |

## 2. 产品边界与部署

### A 级硬要求

- 正式名称：**在役检查系统-指套管数据管理工具**。
- 软件是本地 Windows 企业级专业数据库软件，离线运行。
- 不开发公网网页版本，不依赖云端服务，不上传核电报告或检测数据。
- 软件需要覆盖：数据导入、数据处理、数据管理、二维管板图、三维模型交互、数据可视化、检测报告/对比报告导出和专业设置。
- 既有工程约定的主导航固定为：
  1. 数据工作台
  2. 三维缺陷模型
  3. 数据可视化
  4. 报告与导出
  5. 管状态维护
  6. 软件设置

### 技术约束

- 当前本地架构为 Electron 桌面壳 + Python 标准库 HTTP 服务 + SQLite + 原生 JS/Three.js。
- 默认单机 SQLite；数据访问层应为后续局域网数据库迁移预留接口。
- 运行时依赖和本地 Three.js 必须随软件打包，断网仍可启动。

## 3. 数据导入

### 3.1 原始检测文件导入

支持识别、预览和入库：

- `.ECT`
- `.RPT`/`.rpt`
- `.SUM`
- `.SET`/`.set`
- 相关布局、校准和软件配置文件

原始文件应先解析成标准预览表，再进入本地数据库。预览阶段必须显示解析错误、异常行、无法关联的文件和可导入数量。

### 3.2 表格导入

- 支持 `.xlsx`、`.xls`。
- 支持单文件、批量多文件和选择文件夹导入。
- 支持表头别名、字段映射和导入模板。
- 同时保留原始值和规范化值，不因规范化而丢失原始内容。

### 3.3 报告版本确认

- 同一批次可能有多个分析人员或多个报告版本。
- 系统应列出候选报告版本。
- 最终报告版本必须由操作人员人工选择和确认。
- 未选版本不能删除，应保留为候选版本和审计记录。

### 3.4 导入批次和回滚

每次导入应记录：

- 操作人员、时间、来源路径
- 文件哈希、文件大小和文件类型
- 解析器版本
- 导入批次号和确认状态
- 关联报告版本
- 导入结果、异常和回滚信息

导入应支持进度显示、异常隔离、失败反馈和批次回滚，不能出现“部分导入但用户不知情”。

## 4. 数据模型与审计

业务记录至少保留：

- 基地、机组、大修批次和大修流水号
- 物理管号、堆芯坐标、Row/Column/Entry
- 原始文件、原始报告、数据组和来源路径
- 原始字段、规范化字段、单位和转换方向
- 检测人员、分析人员、仪器、探头和分析阶段
- 缺陷位置、通道、幅值、相位、百分比、长度、宽度、备注
- 校验状态、异常状态和人工确认记录

异常中心至少覆盖：

- 重复采集、重复导入和哈希冲突
- 缺失报告
- ECT 与 RPT 无法关联
- ECT 存在但没有 `ReportEntry`
- 文件名与 `HeaderTube` 不一致
- 管号越界、管号缺失
- Row/Column/Entry 不一致
- 奇偶映射缺失或重复
- 必填字段缺失
- 解析失败、格式损坏和异常行

每条异常尽量定位到：来源文件、批次、报告、工作表、行号、字段和原始值。

## 5. ECT/RPT 文件规则

### 5.1 ECT 文件名和结构

文件名格式：

```text
DIRxxxCxxxIyyy.ECT
```

- `DIRxxx` 对应 `HeaderTube/Row`
- `Cxxx` 对应 `HeaderTube/Col`
- `Iyyy` 对应 `HeaderTube/Entry`
- 导入时必须与 `HeaderTube` XML 逐项校验。
- `.ECT` 是“文件头 + XML 元数据 + 二进制采样数据”的混合格式，不能当作纯文本处理。

### 5.2 管号和标准文件

- 正式管号范围为 1–50。
- `000`、`999` 等校准/标准文件必须单独标识，不进入正式管子缺陷统计。
- 同一基地、同一机组、同一管号出现多个 ECT 时，可能是复测、补采或重复采集：
  - 统计不得重复计数；
  - 原始文件、候选记录和审计记录必须全部保留。

### 5.3 RPT 与 ECT 关联

优先使用：

```text
Calgroup + Filename
```

然后校验：

- Row
- Column
- Entry
- 基地/机组/数据组

`Filepath` 只作来源信息，不能作为主关联键，因为旧报告中可能保存失效的 `Z:\` 或旧电脑路径。

### 5.4 缺陷语义

- `Indication` 非空：一条缺陷/指示记录。
- `Indication` 为空且 `Datapoint=0`：报告明确无缺陷/NDD。
- ECT 存在但没有 `ReportEntry`：未进入报告、未报告或待核查，**不能判为 NDD**。
- 一个 ECT 可对应多个 `ReportEntry`，多个缺陷必须分行保留，不能合并成一条。
- `Location` 如 `P1`、`P1+41`、`P4+42` 是管子轴向位置或偏移位置；不得把一个 ECT 文件错误等同于一个缺陷。
- `P1: 4-6` 等为分析通道/派生通道定义，不能简单当作“第 4 到第 6 个原始通道”。

## 6. 管板、管号与映射

- 每台机组有 50 根物理指套管，外部管号为 1–50。
- 物理管号与堆芯坐标必须分开存储，不能把 Row/Column 直接当作最终显示管号。
- 奇数机组和偶数机组使用不同的管号—堆芯坐标映射。
- 映射必须满足：
  - 管号 1–50 各出现一次；
  - 50 个堆芯坐标各出现一次；
  - 不允许空映射、重复映射或跨奇偶套用。
- 坐标显示格式规范化为 `B8`，不使用 `B08`。
- 2026-10-20 用户官方图确认的校验点：奇数机组15号管和偶数机组42号管均为 `N5`，偶数27号管为 `J15`。
- 此前实现中的 `M5` 为错误映射，不得再作为权威依据；完整对照见《官方管板映射修正_2026-10-20.md》。
- 图纸中个别管号/坐标异常应支持人工核对并留下确认记录。

## 7. 四种管状态与生命周期

> 最新直接用户要求优先于旧聊天中的“对接管/垫管”等叫法。

统一使用：

1. 正常
2. 堵管
3. 移位
4. 换管

### 正常

- 按普通生命周期处理。
- 历次大修之间可按正常规则进行可比性判断。

### 堵管

- 记录状态更新、发生大修、原因、备注和必要的影响范围。
- 堵管后不能删除历史数据。
- 用户明确说明：即使堵管，后续仍可能打开堵头并重新检查，因此不能永久禁止后续数据导入或自动丢弃新检查数据。
- 是否纳入某一统计口径应由状态/配置明确显示，不能静默排除。

### 移位

- “移位”与割管移位属于同一类业务。
- 必须人工录入有符号偏移值、单位、正负方向、发生大修和备注。
- 默认单位为毫米，但单位必须可配置。
- 只允许与同一基地、同一机组的下一次相邻大修比较，不能跨越大修批次。
- 例：F101 管 1 为 `P1+42 mm`，处理结果为移位 `42 mm`；F102 的 `P1` 应与 F101 的 `P1+42` 比较。
- 缺少明确位置、方向或存在多个候选位置时，输出“待确认”，不得猜测。

### 换管

- 表示更换为全新的物理管。
- 历史缺陷永久保留，并标记为换管前生命周期。
- 换管后的新管建立新生命周期。
- 换管后的第一次检查不与换管前缺陷比较，按新管首检处理。
- 若下一次大修再次换管，按新生命周期重新处理。
- 如果“下一次”才发生换管，则上一大修在生命周期仍连续时可以正常比较。
- 换管生效时点必须在配置/确认记录中明确；当前默认按该次检查结束后影响下一次比较。

## 8. R/NI 与对比规则

- `R`：当前缺陷在合法坐标换算后，与指定历史可比大修的同一物理位置已有缺陷相匹配。
- `NI`：历史无同位置缺陷，或换管后新生命周期首次发现。
- 匹配至少考虑：
  - 同一基地、机组和物理管号
  - 同一生命周期
  - 同一 P 位或换算后的同一轴向位置
  - 位置距离/偏移和配置的匹配容差
  - 显示类型是否需要一致应由配置确认
- 位置缺失、位置歧义或候选不唯一时输出“待确认”，不能用 `Datapoint × 任意固定系数` 强行推断物理位置。
- 移位管只比较下一次相邻大修。
- 正常管按连续生命周期比较。
- 换管后首检不与旧管比较。
- “磨损增量”只能来自真实匹配的 R 记录；不能把某一大修的累计深度总和称为增量。
- 20%、40%、50%、65% 等历史分级仅用于图形展示/参考分类，不是验收标准，也不能自动生成工程结论。

## 9. 二维可视化

二维视图至少需要：

- 完整管板/阶梯式管板布局，不能用错误的半圆替代真实构型。
- 奇数机组、偶数机组分别显示和切换。
- 管号 1–50、堆芯坐标和物理位置同时可查。
- 缺陷按可配置分级着色。
- 正常、堵管、移位、换管使用明显但不混淆的状态标识。
- 未报告、缺失报告、NDD 和真实缺陷必须分开显示。
- 点击管号/坐标可查看历次大修、状态变化、缺陷、原始文件和审计记录。
- 支持基地 → 机组 → 大修筛选，并显示当前数据范围和质量状态。

## 10. 三维缺陷模型

- 本地 Three.js 模型，不依赖 CDN 或外部网页。
- 管板位置作为 XY 坐标，历史大修/时间作为时序维度。
- 展示 50 根指套管、压力容器/PRV 相关结构、衰减管/支撑结构和 P1–P6 标识。
- 缺陷点应定位到对应物理管和 P 位/轴向位置，并能查看来源记录。
- 需要有整体视图和单管局部视图，支持旋转、缩放、复位、选管和查看历次缺陷演化。
- 不能假设所有管子长度完全相同；P1–P6 距离应带明确物理参考坐标、单位和来源。
- 模型可以是清晰可追溯的工程简化模型，不要求替代 CAD/设计校核。
- 奇数、偶数映射和数据显示不能串用。

## 11. 数据可视化与分析

必须支持：

- 基地 → 机组 → 大修联动筛选。
- 当前 SQLite 实时数据与历史/参考数据明确区分。
- 当前缺陷分布。
- P1–P5/P1–P6 位置分布。
- 各大修趋势。
- 真实可比记录产生的 R/NI 变化和增量。
- 明确记录驱动的堵管、移位、换管状态分布。
- 缺失数据、未报告、异常和数据质量视图。
- 同一管子的历史详情钻取。

不得：

- 从磨损值反推“换管”或其他状态；
- 把累计深度总和标记为“增量”；
- 把某基地/机组风险结论硬编码成永恒结论；
- 将参考报告中的群厂统计数字直接当作当前数据库事实。

## 12. 报告与导出

需要支持：

- 单次大修检测汇总报告。
- 两次大修对比报告。
- 标准化 Excel。
- Word 报告。
- CSV/Excel 明细和统计表。
- 缺失报告清单。
- 未关联 ECT 清单。
- 重复采集/重复导入清单。
- 文件校验清单。
- 管号/映射错误清单。
- 未解析或待确认缺陷清单。

导出规则：

- 预览和导出必须使用同一数据快照。
- 预览后数据库或配置发生变化时，导出必须阻止并要求重新预览。
- 缺失值保持空白，不使用 `/`、`待填写` 或编造值。
- 报告中保留来源文件、报告版本、解析状态和核查提醒。
- Word 在本地生成；用户可在 Windows 中自行另存为 PDF。
- 不得把某一个基地、机组或报告编号写死到所有模板。
- 报告字段可包括基地、机组、大修、部件、材料、安全等级、仪器、探头、程序、分析人员、缺陷和追溯信息；缺失值留空。

## 13. 专业设置与管理

设置页应支持：

- 基地/机组字典。
- 奇数/偶数映射表。
- 字段字典和表头别名。
- P1–P5/P1–P6 定义、距离和物理参考点。
- 偏移单位、正负方向和匹配容差。
- 缺陷颜色/显示分级。
- 报告模板和字段映射。
- 导入规则、候选报告确认规则和重复处理规则。
- 数据库备份/恢复。
- 本地数据路径和导出路径。
- 解析器版本、数据字典和迁移版本。

## 14. 验收标准

### 数据和导入

- ECT 文件名与 `HeaderTube` 一致性校验有效。
- RPT/ECT 能按 `Calgroup + Filename` 关联并校验 Row/Column/Entry。
- 单文件、批量文件、文件夹导入均可用。
- 多报告版本可人工选择，未选版本可追溯。
- 重复导入可识别，原始数据不丢失。
- 异常行可定位、隔离和回滚。

### 业务逻辑

- 管号严格覆盖 1–50。
- 奇偶映射完整、唯一且不串用。
- 堵管数据可保留并支持后续重新检查。
- 移位 42 mm 示例能正确换算，且不会跨越非相邻大修。
- 换管后首检不会错误标记为旧管 R。
- R/NI 只在真实可比记录上生成，歧义输出“待确认”。

### 可视化和报告

- 二维管板定位准确，状态和缺陷颜色可解释。
- 三维模型、P1–P6 标识和缺陷点可见、可选、可追溯。
- 当前数据、历史参考和质量异常有明确区分。
- 预览与 Word/Excel/CSV 导出内容一致。
- 空值为空白，无虚构字段。

### 本地部署

- 无网络环境可启动。
- Windows 桌面窗口内运行，不暴露网页地址栏作为产品入口。
- 数据库可备份、恢复和升级兼容。

## 15. 冲突和废止内容

以下内容不能作为当前规则：

1. 旧聊天中的“对接管 / 垫管 / 移位 / 正常”四态。  
   当前统一为“正常 / 堵管 / 移位 / 换管”。
2. “堵管后永远不再检测”或自动删除堵管后的数据。  
   与用户最新说明冲突，废止。
3. 任意跨大修批次比较移位管。  
   与用户明确的“只和下一次相邻大修比较”冲突，废止。
4. 从磨损值、趋势或图形反推换管/移位状态。  
   状态必须来自明确的状态记录或人工确认。
5. 把历史 PPT/DOCX 的 20%/40%/50%/65% 分级当作正式工程判据。  
   只能作可视化或参考分类。
6. AI 过去写下的默认假设、演示数据和固定基地/机组结论。  
   没有 A/B/C 级证据时只能保留为参考。

## 16. 尚需用户/业务签字确认

- P1–P6 在不同基地/机组的精确物理定义和距离基准。
- 偏移正负方向、单位换算和匹配容差。
- 外部状态台账的字段格式、导入方式和生效时点。
- 换管状态是在本次检查前还是检查后生效。
- `.xls/.wps/.doc/.ppt` 中少数无法完整解析字段的最终取值来源。
- 图纸中少数管号—坐标异常的现场高清复核结果。
- Word 报告最终模板、签字栏和各基地差异字段。
