# 正式版项目结构

## 版本边界

`08_Qt移植版/` 是项目唯一主版本和后续软件开发、修复、测试的工作目录。`01_当前软件/软件正式版_20261021/` 是旧 Electron 版，只读用于对照；历史备份仅供追溯。
项目根目录只保留 `启动Qt主版本.cmd` 一个日常入口，入口转向本目录的 Qt 启动链。Qt 运行数据位于 `user-data/`，与旧版用户数据相互独立，不自动迁移或合并。

本目录保留 Qt 桌面壳及业务源码、资源、构建产物和验证代码。根目录之外的原始资料按类别归档；测试生成的数据库、导出、缓存和截图统一放入项目根目录的 `05_测试与验证/03_自动化临时产物/`。

## 资料分层

| 目录 | 内容 | 处理原则 |
| --- | --- | --- |
| `01_需求与记忆` | 用户需求、聊天记录、记忆 | 原文只读保存，不作为业务数据自动写入 |
| `02_业务参考资料` | 报告、图纸、图片、说明 | 用于报告样式、字段和规则核对 |
| `03_原始验证数据` | ECT、RPT、SUM、PDF 和验证台账 | 只读测试源，不在测试中覆盖 |
| `04_三维模型工程` | 模型源文件、查看器和校验资料 | 与桌面运行时的模型资源分开 |
| `05_历史导出与验证输出` | Excel、截图、验证证据 | 可删除、可重新生成，不是源码依赖 |
| `06_台账与计划` | 台账、年度计划、表头配置 | 作为人工导入样例和报告配置资料 |
| `07_历史开发资料` | 早期网页原型、临时诊断脚本、开发记录 | 与桌面源代码完全分区，不参与运行和打包 |

## 备份

整理前的完整软件快照位于工作区 `03_历史版本备份/整理前版本与完整备份/软件部分0828_完整备份_20261021`。由于旧版正在运行，唯一未复制的是被 Electron 锁定的 `.user-data/Network/Cookies` 缓存文件；该文件是可重建缓存，不包含应用数据库或源码。

本次整理范围、复制数量、备份限制和验证结果见 `整理与备份记录_2026-10-21.md`。

## 工作区整理与占用兼容

- 根目录仅保留 `启动Qt主版本.cmd` 作为软件启动入口；其模板为本目录 `scripts/start-current-version.cmd`。
- `02_项目原始资料` 保存原始需求、业务参考、检测数据、模型工程及台账。
- `03_历史版本备份` 保存旧版本原件、完整备份及旧启动脚本。
- `04_开发归档` 保存网页原型、诊断脚本、截图、过程记录和整理日志。
- 同卷目录移动不复制业务数据；原始备注、表格、数据库均不改写。
- 旧 Electron 版软件目录内的 `项目资料`、`tmp`、`data`、`output`、`release` 和 `.user-data` 是为兼容旧版代码保留的目录联接；它们不是用户快捷入口，也不是重复副本。
- `.git` 及 `.gitattributes` 属于工作区元数据，不作为业务资料搬动。

从本版本目录执行只读资料核对：

```powershell
python scripts/verify_migration.py --source-project ../.. --output output/migration/verification_after_classification.json
```

关闭旧软件、模型预览和打开的资料后，完成剩余物理搬移：

```powershell
pwsh -NoProfile -File scripts/organize-workspace.ps1 -WorkspaceRoot ../.. -Apply
```

脚本只操作明确列出的路径；遇到目标冲突拒绝覆盖，遇到占用则保留原件并记录。查看 `04_开发归档/05_整理记录` 中的 JSONL 日志可追溯每项旧位置、新位置和实际结果。
